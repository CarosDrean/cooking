## Problemas encontrados

### [P1] CRÍTICO: `getMatchQuery` asigna matchedMeal incorrecto por substring matching

- **Ubicación:** `server/src/services/importPipeline.ts` líneas 108-113, función `getMatchQuery`
- **Descripción:** El fallback `recipe.title.toLowerCase().includes(q.terms.toLowerCase())` hace substring matching sin `\b`, causando que recetas como "Eggplant" matcheen "egg" (keyword de desayuno) o "Goat" matchee "oat" (keyword de desayuno de "avena"). Esto provoca que TODAS las recetas candidatas tengan `matchedMeal: "desayuno"`, inutilizando el `diverseTop`.
- **Pasos para reproducir:**
  1. Tener un perfil con `usualDishes.desayuno` que incluya platos con "huevo" y "avena" (genera keywords "egg", "oat" para themealdb)
  2. Ejecutar POST /api/import/auto-import
  3. Observar que 100% de resultados tienen matchedMeal="desayuno"
- **Comportamiento esperado:** "Mbuzi Choma (Roasted Goat)" debería tener matchedMeal="almuerzo" o "cena", no "desayuno"
- **Evidencia:**
  ```
  "Mbuzi Choma (Roasted Goat)" → matchedMeal: "desayuno" (porque "Goat" contiene "oat")
  "Sichuan Eggplant" → matchedMeal: "desayuno" (porque "Eggplant" contiene "egg")
  "Chocolate Avocado Mousse" → matchedMeal: "desayuno" (por "avocado" de "palta")
  "Croatian lamb peka" → matchedMeal: "desayuno" (por substring match con "meat" o similar)
  ```

### [P2] MEDIO: `sin-lactosa` duplicado en dietas de recetas importadas

- **Ubicación:** `server/src/services/themealdb.ts` líneas 73-85, función `guessDiet`
- **Descripción:** Cuando una receta no tiene ingredientes animales (`hasAnimal=false`), la línea 81 asigna `["vegano", "vegetariano", "sin-lactosa"]`. Luego la línea 83 (`if (!hasDairy)`) también evalúa true (porque si no hay animal, no hay lácteos), agregando otro `"sin-lactosa"`. Resultado: `['vegano', 'vegetariano', 'sin-lactosa', 'sin-lactosa']`.
- **Pasos para reproducir:**
  1. Importar "Bajan Salt Bread Recipe" (pan vegano sin lácteos)
  2. GET /api/recipes → buscar tmdb-53456
  3. Ver `diets: ['vegano', 'vegetariano', 'sin-lactosa', 'sin-lactosa']`
- **Comportamiento esperado:** `['vegano', 'vegetariano', 'sin-lactosa']` (sin duplicados)
- **Evidencia:**
  ```json
  {"id":"tmdb-53456","title":"Bajan Salt Bread Recipe","diets":["vegano","vegetariano","sin-lactosa","sin-lactosa"]}
  ```

### [P3] BAJO: `inferSuitableFor` propaga matchedMeal incorrecto a suitableFor

- **Ubicación:** `server/src/services/importSources.ts` líneas 573-609, función `inferSuitableFor`
- **Descripción:** El parámetro `meal` que recibe `inferSuitableFor` viene de `query.meal`, que ya puede ser incorrecto (desayuno en vez de almuerzo). Esto hace que recetas claramente de almuerzo/cena se etiqueten como `['desayuno', 'almuerzo']`.
- **Pasos para reproducir:** Ver cualquier receta importada — todas tienen `suitableFor: ['desayuno', 'almuerzo']`
- **Comportamiento esperado:** Recetas como "Croatian lamb peka" deberían ser `['almuerzo', 'cena']`
- **Nota:** Este es un síntoma de P1. Si se corrige P1, este problema se mitiga parcialmente.

### [P4] BAJO: Las bebidas (drinks) siempre retornan 0 en la importación

- **Ubicación:** `server/src/services/importPipeline.ts` líneas 247-279
- **Descripción:** El adaptador de CocktailDB se ejecuta pero siempre retorna 0 bebidas. Posiblemente porque el perfil no tiene CocktailDB como fuente habilitada o porque las queries de bebidas no retornan resultados.
- **Pasos para reproducir:** Ejecutar auto-import → `importedDrinkCount: 0`
- **Comportamiento esperado:** Al menos algunas bebidas importadas de CocktailDB

## Recomendaciones

1. **P1 (crítico):** Modificar `getMatchQuery` para que el fallback también use `\b` word boundaries, o directamente eliminar el fallback de substring y retornar un meal por defecto más razonable (ej: "almuerzo" en vez de `queries[0]`).
2. **P2 (medio):** Agregar un `Set` o filtro de duplicados en `guessDiet` antes del return (`return [...new Set(diets)]`).
3. **P3 (bajo):** Se resuelve al corregir P1. Aún así, `inferSuitableFor` podría mejorarse usando heurísticas basadas en categorías de TheMealDB (ej: "Breakfast" → desayuno, "Beef"/"Chicken"/"Seafood" → almuerzo/cena).
4. **P4 (bajo):** Investigar por qué CocktailDB no retorna bebidas. Posiblemente las queries "coffee", "juice", etc. necesitan ajustes.

## Resumen del fix de importación

| Fix prometido | ¿Funciona? | Evidencia |
|---|---|---|
| `guessDiet()` separa huevos de lácteos, asigna `sin-lactosa` a recetas sin lácteos | ✅ Sí (pero con duplicado P2) | Recetas con huevo pero sin lácteos tienen `sin-lactosa` |
| Keywords de `usualDishes` generan búsquedas en TheMealDB | ✅ Sí | Se generan queries con "chicken", "stew", "beef", etc. |
| Palabras matchean con `\b` word boundary | ✅ Parcial — `termMatchesTitle` usa `\b`, pero `getMatchQuery` tiene fallback sin `\b` | "Goat" no matchea "oat" en `termMatchesTitle`, pero sí en `getMatchQuery` |
| `diverseTop` diversifica floor(maxResults/3) por tipo de comida | ❌ No — todas las recetas tienen el mismo `matchedMeal`, así que diversificar es imposible | 100% desayuno en ambas ejecuciones |
