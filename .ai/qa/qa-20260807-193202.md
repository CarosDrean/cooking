## Problemas encontrados

### [P1] `matchedMeal` asigna todas las recetas a "desayuno" por falsos positivos de substring

- **Ubicación:** `server/src/services/importPipeline.ts`, línea 194
- **Descripción:** La búsqueda de query coincidente usa `.includes()`, lo que genera falsos positivos con keywords de desayuno que son subcadenas de otras palabras en títulos de recetas.
- **Pasos para reproducir:**
  1. Tener perfil "Oscar" con `usualDishes.desayuno: ["avena con pan", "pan con huevo y avena", "pan con palta y avena"]`
  2. Las keywords se traducen a `["oat", "bread", "egg", "avocado"]` con `meal: "desayuno"`
  3. Ejecutar `POST /api/import/auto-import`
  4. Revisar los `matchedMeal` en la respuesta
- **Comportamiento esperado:** Cada receta debería tener `matchedMeal` según la query que la generó. Las recetas de "chicken" o "beef" deberían ser `almuerzo`, no `desayuno`.
- **Comportamiento real:** Todas las recetas obtienen `matchedMeal: "desayuno"` porque:
  - `"oat"` coincide en títulos como "Goat", "Cro**oat**ian"
  - `"egg"` coincide en títulos como "**egg**plant"
  - `"bread"` coincide en títulos como "flat**bread**s"
  - `"avocado"` coincide directamente
  - El `find()` retorna la primera query coincidente, que por orden de inserción suele ser de desayuno
- **Evidencia (respuesta real de la API):**
  ```
  "Mbuzi Choma (Roasted Goat)"         → matchedMeal: "desayuno"  (por "oat" en "Goat")
  "Traditional Croatian Goulash"       → matchedMeal: "desayuno"  (por "oat" en "Croatian")
  "Roasted Eggplant With Tahini..."    → matchedMeal: "desayuno"  (por "egg" en "Eggplant")
  "Griddled flatbreads"                → matchedMeal: "desayuno"  (por "bread" en "flatbreads")
  "Chinese Tomato Egg Stir Fry"        → matchedMeal: "desayuno"  (por "egg")
  "Air Fryer Egg Rolls"                → matchedMeal: "desayuno"  (por "egg")
  ... (12 de 12 son "desayuno")
  ```

### [P1] `diverseTop` no logra diversificar porque solo hay recetas en el bucket "desayuno"

- **Ubicación:** `server/src/services/importPipeline.ts`, líneas 31-56 (`diverseTop`)
- **Descripción:** `diverseTop` intenta tomar `floor(maxResults/3) = 4` recetas de cada meal type, iterando sobre `["desayuno", "almuerzo", "cena"]`. Como todas las recetas tienen `matchedMeal: "desayuno"` (ver problema anterior), los loops de almuerzo y cena no encuentran candidatos. Luego rellena con más recetas del bucket "desayuno".
- **Pasos para reproducir:** Los mismos que el problema anterior.
- **Comportamiento esperado:** ~4 recetas con `matchedMeal: "desayuno"`, ~4 con `matchedMeal: "almuerzo"`, ~4 con `matchedMeal: "cena"`.
- **Comportamiento real:** 12/12 recetas con `matchedMeal: "desayuno"`.
- **Distribución real observada:**
  | Meal      | Count | Percentage |
  |-----------|-------|-----------|
  | desayuno  | 12    | 100%      |
  | almuerzo  | 0     | 0%        |
  | cena      | 0     | 0%        |

### [P2] `guessDiet` duplica la dieta "sin-lactosa"

- **Ubicación:** `server/src/services/themealdb.ts`, líneas 81-83
- **Descripción:** Para recetas sin productos animales, se asigna `["vegano", "vegetariano", "sin-lactosa"]`. Luego, en la línea 83, si no hay lácteos se vuelve a agregar `"sin-lactosa"`. Como una receta vegana siempre es sin lácteos, el array queda con "sin-lactosa" duplicado.
- **Pasos para reproducir:**
  1. Importar una receta vegana de TheMealDB
  2. Revisar `diets` en la respuesta
- **Comportamiento esperado:** `["vegano", "vegetariano", "sin-lactosa"]`
- **Comportamiento real:** `["vegano", "vegetariano", "sin-lactosa", "sin-lactosa"]`
- **Evidencia (recetas afectadas):**
  ```
  Vegan banh mi              → ["vegano", "vegetariano", "sin-lactosa", "sin-lactosa"]
  Syrian Bread               → ["vegano", "vegetariano", "sin-lactosa", "sin-lactosa"]
  Chtitha Batata             → ["vegano", "vegetariano", "sin-lactosa", "sin-lactosa"]
  ... (múltiples recetas)
  ```

### [P2] `mapMealToRecipe` asigna `suitableFor` fijo ignorando la categoría de TheMealDB

- **Ubicación:** `server/src/services/themealdb.ts`, línea 154
- **Descripción:** Todas las recetas de TheMealDB se marcan con `suitableFor: ["almuerzo", "cena"]` sin importar que la API de TheMealDB tiene una categoría "Breakfast" que podría usarse para asignar `suitableFor: ["desayuno", "almuerzo"]`.
- **Pasos para reproducir:**
  1. Buscar recetas con query "breakfast" en TheMealDB
  2. Revisar el campo `strCategory` (TheMealDB devuelve "Breakfast" para recetas de desayuno)
  3. Observar que `suitableFor` sigue siendo `["almuerzo", "cena"]`
- **Comportamiento esperado:** Si `strCategory === "Breakfast"`, asignar `suitableFor: ["desayuno", "almuerzo"]`
- **Comportamiento real:** Siempre `["almuerzo", "cena"]`
- **Nota:** Algunas recetas importadas con búsqueda "breakfast" sí tienen `suitableFor: ["desayuno"]` en la DB, lo que sugiere que fueron importadas por una ruta diferente (`/themealdb/auto-import`) que sí usa la categoría.

### [P3] Pocas recetas locales de desayuno

- **Ubicación:** `server/data/db.json` (recetas locales)

## Análisis de distribución

### Antes del fix de diversificación (estado actual observado)

| Meal      | Count | %     |
|-----------|-------|-------|
| desayuno  | 12    | 100%  |
| almuerzo  | 0     | 0%    |
| cena      | 0     | 0%    |

**Conclusión:** El fix de diversificación **no está funcionando**. La distribución es 100% desayuno, peor que antes (donde era 100% almuerzo).

### Causa raíz identificada

El `find()` en `importPipeline.ts:194` produce falsos positivos masivos porque las keywords de desayuno ("oat", "bread", "egg", "avocado") son subcadenas de palabras muy comunes en títulos de recetas de TheMealDB. Esto asigna `matchedMeal: "desayuno"` a prácticamente todas las recetas, rompiendo completamente la diversificación.

## Recomendaciones

1. **Fix crítico (P1):** Cambiar `importPipeline.ts:194` para usar coincidencia por palabra completa en lugar de substring. Ejemplo:
   ```ts
   // En lugar de:
   filteredQueries.find((q) => recipe.title.toLowerCase().includes(q.terms.toLowerCase()))
   // Usar:
   filteredQueries.find((q) => {
       const regex = new RegExp(`\\b${q.terms.toLowerCase()}\\b`);
       return regex.test(recipe.title.toLowerCase());
   })
   ```
   O alternativamente, hacer el matching contra `q.terms.split(/\s+/)` y verificar que al menos una palabra completa coincida.

2. **Fix (P2):** En `themealdb.ts:81-83`, evitar duplicar "sin-lactosa". Si `!hasAnimal`, ya se está asignando "sin-lactosa", no hace falta volver a agregarlo en línea 83:
   ```ts
   if (!hasAnimal) {
       diets.push("vegano", "vegetariano", "sin-lactosa");
   } else if (!hasMeat) {
       diets.push("vegetariano");
       if (!hasDairy) diets.push("sin-lactosa");
   } else if (!hasDairy) {
       diets.push("sin-lactosa");
   }
   ```

3. **Mejora (P2):** En `themealdb.ts`, usar `strCategory === "Breakfast"` para asignar `suitableFor: ["desayuno", "almuerzo"]` en lugar del fijo `["almuerzo", "cena"]`.

4. **Mejora (P3):** Agregar más recetas locales de desayuno al seed (`server/data/recipes.json`).

5. **Sugerencia:** Agregar un log de distribución en `diverseTop` para facilitar debugging futuro:
   ```ts
   console.log(`diverseTop distribution: desayuno=${countDesayuno}, almuerzo=${countAlmuerzo}, cena=${countCena}`);
   ```
